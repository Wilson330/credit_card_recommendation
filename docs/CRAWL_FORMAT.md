# 爬蟲匯出格式

爬蟲交給後端匯入的檔案格式。以 0908 那包(`db/crawl/card_rewards_export_0908.json`)為基礎:原本的欄位不變,另外加了幾個選填欄位。0908 的檔案不用改,照樣可以匯入。

**原則:照抄網頁上的原文,不用判斷。** 店名、方案名、括號裡的限制都照網頁寫的存。「這一列是店家還是行動支付」「數字含不含基本回饋」這類判斷,由後端這邊處理。

## 檔案

- JSON(建議):最外層是陣列,每一列是一個物件。
- CSV 也可以:第一列是欄位名稱,UTF-8 編碼(Excel 存檔時選「CSV UTF-8」)。
- 一個檔案可以放好幾張卡。檔名建議 `card_rewards_export_YYYYMMDD.json`,放在 `db/crawl/`。

## 一列代表什麼

一列 = **一張卡 × 一個等級 × 一個方案 × 網頁上列出的一個名稱**,加上回饋率。

- 同一家店在三個等級都有回饋,就是三列。即使三個等級的數字一樣,也要每個等級各一列。
- 卡片沒有等級時,`card_level` 填空字串 `""`。0908 吉鶴卡填的 `Standard` 也可以。

## 必填欄位

| 欄位 | 型別 | 說明 | 範例 |
|---|---|---|---|
| `bank_name` | 文字 | 銀行 | `國泰世華` |
| `card_name` | 文字 | 卡名。新卡要先在 `backend/cards.yaml` 設定,匯入時用這個名稱對照 | `CUBE卡` |
| `card_level` | 文字 | 等級或方案,沒有就填 `""` | `Level 2`、`任意選` |
| `scheme_name` | 文字 | 網頁上的方案或分類名稱 | `樂饗購`、`國內日系特店` |
| `merchant_name` | 文字 | 網頁上列出的名稱,照抄,括號也保留 | `金子半之助(限週一至週四)` |
| `reward_rate` | 數字 | 回饋率,單位 %,寫數字不要加 % 符號 | `2.5` |

`merchant_name` 不一定是店家。網頁上列在方案底下的東西都照抄成一列,例如:

| 網頁上的內容 | 照抄成 merchant_name |
|---|---|
| 店家 | `鼎泰豐`、`台北101` |
| 一般消費 | `國內一般消費`、`一般消費(不含保費)` |
| 行動支付 | `LINE Pay`、`全支付國內合作通路` |
| 國家或整類消費 | `日本`、`國內飯店住宿`、`國內餐飲(不含餐券)` |

## 選填欄位

有的話會讓後端的判斷更準,沒有也能匯入。

| 欄位 | 型別 | 說明 | 範例 |
|---|---|---|---|
| `section` | 文字 | 這一列在網頁上所屬的段落標題,照抄。最有幫助的欄位:看到「指定行動支付」就知道底下都是行動支付 | `指定行動支付`、`海外指定國家` |
| `source_url` | 文字 | 這一列出自哪個網頁 | `https://www.cathaybk.com.tw/...` |
| `valid_from` | 日期 `YYYY-MM-DD` | 活動開始日。還沒到的列匯入時略過 | `2026-10-01` |
| `valid_to` | 日期 `YYYY-MM-DD` | 活動結束日。已過的列匯入時略過 | `2026-12-31` |
| `id` | 數字或文字 | 列的編號,格式檢查報錯時會一起列出,方便找 | `862` |
| `updated_at` | 文字 | 爬取時間 | `2026-10-17 19:11:07` |

其他欄位名稱不會出錯,但匯入時會忽略,格式檢查會提醒。

## 範例

```json
[
  {"bank_name": "國泰世華", "card_name": "CUBE卡", "card_level": "Level 2",
   "scheme_name": "樂饗購", "merchant_name": "鼎泰豐", "reward_rate": 3.0,
   "section": "指定餐飲通路", "source_url": "https://www.cathaybk.com.tw/...", "updated_at": "2026-10-17 19:11:07"},
  {"bank_name": "玉山銀行", "card_name": "Unicard", "card_level": "任意選",
   "scheme_name": "百大特店", "merchant_name": "LINE Pay", "reward_rate": 2.5,
   "section": "指定行動支付"},
  {"bank_name": "聯邦銀行", "card_name": "吉鶴卡", "card_level": "",
   "scheme_name": "國內人氣餐廳", "merchant_name": "金子半之助(限週一至週四)", "reward_rate": 10.0,
   "valid_from": "2026-10-01", "valid_to": "2026-12-31"}
]
```

## 交檔前先檢查

在專案根目錄執行,不需要資料庫:

```bash
python -m backend.importer db/crawl/card_rewards_export_20261017.json --check
```

```
=== db/crawl/card_rewards_export_20261017.json:1236 列 ===
  CUBE卡:867 列、9 個方案、等級 Level 1、Level 2、Level 3
  Unicard:297 列、1 個方案、等級 UP選、任意選、簡單選
  吉鶴卡:72 列、7 個方案、等級 Standard

格式檢查通過。
```

- **錯誤**:要修正才能匯入,例如缺欄位、`reward_rate` 不是數字或超過 100、日期格式不對。最後會顯示「格式檢查沒有通過」。
- **警告**:不擋匯入,但請看一下,例如同一家店出現兩次而回饋率不同、名稱前後有空白、`cards.yaml` 還沒有這張卡。

檢查通過就可以交檔。

## 交檔之後(後端這邊)

1. **標記**:每個 `merchant_name` 原文標成店家、一般消費、行動支付、整類消費或地區、略過其中一種,存在 `db/crawl/labels.yaml`。標記過的原文下次自動沿用,只有新出現的需要判斷。`section` 有填的話,這一步會準很多。
2. **對照店家**:`importer --dry-run` 列出對不到的店名,確認是既有的店(`--map`)還是新店(`--new`)。
3. **匯入**:寫進資料庫,重新匯出 `db/seed.sql`。

細節見 [backend/README.md](../backend/README.md) 第 6 節。
