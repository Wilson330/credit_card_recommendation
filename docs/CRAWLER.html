爬蟲說明:agent 介入的爬蟲

要讓 App 支援一張新卡,得先從銀行官網抓到「哪些店、幾 %」。每家銀行網頁長得都不一樣,寫一支通吃的爬蟲很難;這一版的做法是讓 agent(Claude)負責找網頁、讀懂網頁,並把讀法寫成一份「食譜」,之後由程式照食譜執行,結果固定、可以重跑。程式檢查完,agent 先當第一線審核,再交給人做最後確認。

1整體流程

對 Claude 說「爬國泰的 CUBE 卡」,會觸發 skill crawl-card,依序走完下面六步。藍框是 agent 與程式自動做的事,橘框是要人確認的檢查點。每一步都會留下檔案(框內最下面一行),重爬既有的卡可以直接從第 ③ 步開始。

2每一步在做什麼

右欄以聯邦吉鶴卡為例。

  1. 找網頁 ✋ 檢查點 1

    先查 crawler/banks.yaml 有沒有這家銀行的記錄;沒有才用搜尋引擎。以銀行官網為準,比較網站與新聞只當線索。找到後列出頁面清單(網址、角色:回饋名單/條款/活動),請人確認,確認後寫回 banks.yaml,下次不用再找。

    例搜尋引擎只找到比較網站。直接到聯邦信用卡官網,發現是單頁應用(HTML 只有空殼),從 JS 找到卡片清單 API,再找到吉鶴卡內容所在的 HTML 片段。不需要模擬瀏覽器。

  2. 寫食譜 ✋ 檢查點 2

    agent 讀網頁,寫一份設定檔:每個方案的名單從哪裡到哪裡、用什麼符號切開、回饋率多少。每個數字都要附上網頁原文當依據。給人看方案、回饋率、預計列數。

    例「從『指定人氣餐廳:』抓到『一般消費回饋無上限』,用『、』切開,回饋率 10%,依據『人氣餐廳最高現折10%』」。

  3. 執行爬蟲

    程式照食譜執行:抓網頁(遵守 robots.txt、請求間隔 3 秒、存快取)、解析、輸出符合 docs/CRAWL_FORMAT.md 的匯出檔,條款頁面另存成文字檔。網頁沒變時,重跑結果完全相同。

    例72 列,7 個方案。網頁改版、食譜找不到錨點時直接失敗,不會默默產出錯的資料。

  4. 自動檢查

    確認「抄得對不對」:店名有沒有逐字出現在網頁上、回饋率合不合理、有沒有沒切乾淨的名稱或重複列,並跟上一次爬的結果(或 0908)比較。

    例68 個店名與 0908 完全相同;一般消費 4 列名稱照抄網頁,與 0908 不同。

  5. agent 審核

    agent 把網頁和匯出檔對照著看:有沒有漏抓或多抓、活動期間對不對、新舊版本注意事項有沒有矛盾、後端寫規則時要注意什麼。寫成審核報告,分「需要人決定」「已確認沒問題」「給後端參考」。

    例發現活動頁的注意事項還是上半年的舊版;「人氣餐廳 10%」其實是每家不同的現場折抵(例如滿 1,000 折 100)。

  6. 使用者審核,交接 ✋ 檢查點 3

    人看審核報告做決定;要修就改食譜重跑。確認後:新卡交給 add-card skill 寫規則並匯入;既有的卡跑 importer --dry-run 看影響。

    例--dry-run:4 個方案的店家全部對得到,沒有未標記的列。

3兩種解析方式:食譜與模組

大部分網頁用食譜描述就夠了;資料散在網頁好幾個地方、要拼湊起來的,寫成 Python 模組。crawler/run.py 有食譜就用食譜,沒有就找模組。

食譜 crawler/sites/<卡>.yaml 預設

適合:名單是一段連續文字 
- scheme_name: 國內人氣餐廳
  list:
    after: 指定人氣餐廳：
    until: 一般消費回饋無上限
    separators: 、
  rate: 10
  rate_evidence: 人氣餐廳最高現折10%
  • agent 寫、人看得懂,不用寫程式
  • 錨點或依據原文找不到就報錯
  • 範例:聯邦吉鶴卡

模組 crawler/<卡>.py

適合:資料要從好幾處拼起來 
方案名、LEVEL2 回饋率 ← 方案卡片標籤
段落「日常採買」     ← 卡片裡的格子標題
LEVEL1 回饋率 1.3%   ← 頁面底部彈窗的表格
  • 台新的一列資料來自三個地方;Chill刷 的回饋率寫在格子標題、Pay著刷 的「店家」寫在標題文字裡
  • 範例:台新Richart卡

4自動檢查

格式由 python -m backend.importer --check 負責;這裡檢查的是「抄得對不對」。結果寫在 crawler/reports/<卡>_<日期>.md。

檢查等級內容
溯源錯誤店名、段落要逐字出現在網頁上(忽略空白)。擋解析錯誤,也擋 AI 編造
回饋率錯誤大於 0,且不超過網頁上的最高「最高 X%」
回饋率出處警告數字沒出現在網頁上,可能是推算的
分隔符號、句子、過長警告名稱可能沒切乾淨,或其實是說明文字
重複警告/提示同一等級、方案、名稱出現多次
等級警告各等級的名單應該一樣
期間警告/提示已過期或還沒開始的活動
差異報告跟上一次爬的結果或 0908 比:新增、消失的方案與名稱,回饋率變化
自動檢查第一次跑就抓到真的錯

台新第一次跑時,溯源檢查抓到 Chill刷 的段落名稱是程式拼出來、網頁上不存在的字串,也抓到飯店名單最後一家多帶了「。」。

6怎麼執行

在專案根目錄、Anaconda Prompt 中執行(沒 activate 時抓 https 會出現 SSL module is not available)。平常用法是直接跟 Claude 說要爬哪張卡;下面是手動執行的指令。

# 安裝
pip install -r crawler/requirements.txt

# 爬一張卡(有快取就讀快取;--refresh 重新抓網頁)
python -m crawler.run ubot_jiho
python -m crawler.run ubot_jiho --refresh
python -m crawler.run ubot_jiho --compare db/crawl/card_rewards_export_0908.json

# 格式檢查與匯入預覽(--dry-run 需要本機資料庫,不會寫入)
python -m backend.importer db/crawl/card_rewards_export_20261110_ubot_jiho.json --check
python -m backend.importer db/crawl/card_rewards_export_20261110_ubot_jiho.json --dry-run

# 測試(不連網路)
python -m pytest crawler/tests -q

8決定與待討論

  • 已確定回饋率照抄網頁、不加總。網頁寫「加碼 4% + 一般消費 1%」就是兩列,由後端決定怎麼疊加Wilson
  • 已確定以網頁為準,0908 只拿來比較,不當標準答案Wilson
  • 已確定匯出檔一卡一檔(之後也是一張一張加入)Wilson
  • 已確定官網頁面經人確認後存在 crawler/banks.yamlWilson
  • 已確定台新維持模組;遇到第二家同類型網頁再考慮讓食譜支援Wilson
  • 已確定圖片資料、模擬瀏覽器(Playwright)遇到再做Wilson
  • 待決定方案名照抄網頁還是用整理過的名稱?吉鶴卡網頁標題含數字(「嚴選日系名店最高5.5%」),每季會變;建議抄名單標籤(「指定日系名店」)。要改 cards.yaml,先用 CUBE 驗證再決定Wilson
⚠️ 新的吉鶴卡匯出檔先不要匯入

回饋率改成照抄後,國內日系特店是 4%、日本熱門商店是 3%(加碼的部分)。cards.yaml 目前寫吉鶴卡「不疊加一般消費」,要先改成 stacks_with_general: true 才算得對;--dry-run 不會報這個錯。這件事要跟 cards.yaml 的其他修改一起好好 review。
